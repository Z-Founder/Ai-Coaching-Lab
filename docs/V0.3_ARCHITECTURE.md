# AI Coaching Lab — V0.3 Architecture

Status: Step 7 implementation contract (local development; no production deployment).

## Governance

Safety & Human Dignity → User Agency & Privacy → Coaching Effectiveness → Engagement / Growth / Commercialization.

The Constitution, Product Principles and V0.3 Boundaries constrain this architecture.
No automated third-party contact, hidden profiling, research opt-in or provider keys in the browser.

## Turn pipeline

Interaction Layer → Consent & Context Assembler → Safety Router.

- Safety Mode → Safety Response Engine → Response Validator → User.
- Normal / Elevated → Relationship Engine → Coaching Orchestrator → Intervention Router
  → Question / Reflection / Challenge / Action → Provider-neutral Model Adapter
  → Response Validator → User.

Connected modules: Memory Engine, Track / Follow-up Engine, Pattern Recognition,
Outcome Evaluation, Analytics, Resource Prescription and Knowledge Layer.
The orchestrator owns TurnPlan; a model cannot grant consent or override policy.
Safety veto applies to interventions, challenge and resources. Assessment failures fail closed.

## Change Loop

Observe → Understand → Ask → Reflect → Challenge → Decide → Act → Track → Learn → Adapt → Observe.

This is not a mandatory linear sequence: skip, backtrack and repetition are valid.
Safety Mode suspends it. Challenge always requires NORMAL safety, adequate cognitive
capacity and explicit permission. No action plan is a valid outcome.

## Hybrid Progressive Cloud Architecture

| Plane | Contract | V0.3 implementation |
| --- | --- | --- |
| Identity Vault | IdentityStore | Separate interface; no login or identity collection |
| Cloud Coaching Vault | CoachingStore | In-memory dev adapter; future durable canonical source |
| IndexedDB Local Cache | LocalCacheStore | Opt-in local memory cache; no raw chat persistence by default |
| Analytics Plane | AnalyticsStore | Allowlisted content-free in-memory events; no transport |
| De-identification Pipeline | DeIdentificationPipeline | Development implementation; removes all free text |
| R&D Corpus | ResearchCorpusStore | Separate IDs and consent gate; no production export |

IndexedDB provides local cache / offline resilience, never the future sole source of truth.
Identity fields and coaching text never share a domain record. Research uses independent
research_id and research_session_id, never a production subject_id. Corpus is a derived
product after explicit research consent, not a production mirror. De-identified and
pseudonymized records remain sensitive; there is no claim of absolute anonymity.

## Domain and policy

CoachingTurn contains input, context, SafetyAssessment, RelationshipAssessment, stage,
TurnPlan, InterventionPlan, validated response, memory proposals, action/follow-up and outcomes.
Only structured reason codes are retained, never hidden chain-of-thought.

Evidence tiers describe a specific method + use case: A strong empirical support;
B moderate/context-specific support; C established practice; D heuristic/philosophical;
E contested/insufficient evidence. This dev registry uses conservative D/E labels for
untested local implementations; it makes no treatment efficacy claims.

Memory layers: session, Working Hypothesis, Confirmed Pattern. Hypotheses expire at
14 days OR 3 distinct relevant sessions, whichever comes first. Confirmation is explicit;
editing, rejecting and deleting are user-controlled. Hypotheses have lower routing weight.
Sensitive diagnosis/personality/dangerousness/intelligence labels cannot be auto-confirmed.

Proactive care defaults OFF. Consent-signal invitations obey a 30-day rejection cooldown
and permanent do-not-ask preference. No scheduler or notification delivery in V0.3.
Normal resources: zero or one per session, opt-in, absent in low-load and Safety Mode.
Safety resources are managed separately, with no automatic location inference or contact.

## Failure boundaries and validation

Safety evaluator failure → conservative Safety Mode, never NORMAL.
Model timeout/unavailability → preserve input and local reflection fallback.
Memory transaction failure → show not-saved status; never claim successful persistence.
Analytics failure → continue coaching. Resource failure → omit resource.
All provider output passes schema, policy, length and safety validation before display.
MockModelAdapter runs without credentials. OpenAI placeholder is disabled and server-only.

## Development limits

Rule-based local safety evaluation combines context, explicit intent/immediacy/capability,
recent history and persistence; it is not a clinically validated semantic detector.
Public deployment requires specialist safety review and evaluation, localized verified
crisis resources, provider/data retention decisions, deletion policy and age scope.
No production cloud, real LLM, RAG, third-party notification or research ingestion is deployed.
