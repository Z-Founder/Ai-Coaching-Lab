# AI Coaching Lab — V0.3 Product Boundaries

本文档记录 V0.3 的 Founder Decisions，并冻结 Safety、Privacy、Memory 与 Measurement 的产品边界。

## 1. Governance Priority

发生原则冲突时，优先级为：

**Safety & Human Dignity → User Agency & Privacy → Coaching Effectiveness → Engagement / Growth / Commercialization**

较低层级不得覆盖较高层级。

## 2. Safety Mode and Third-party Contact

V0.3 不允许 AI 自动联系任何第三方。

包括：

- Trusted Contact
- 家庭成员
- 朋友
- 医生
- 警方
- 急救机构
- 雇主
- 保险机构

Safety Mode 可以：

- 降低认知负担；
- 暂停普通 Coaching；
- 鼓励现实世界帮助；
- 向用户展示可信任联系人或紧急资源；
- 询问用户是否希望主动联系他们。

不得静默分享聊天内容。

Trusted Contact 属于未来能力。

第一代 Trusted Contact 默认采用：

**user-initiated contact / explicit confirmation。**

任何“预授权自动通知”都必须作为未来独立安全功能研究，并接受临床、法律与隐私审查。

## 3. Proactive Care

主动关怀：

**Default OFF。**

必须 Opt-in。

再次邀请开启只能基于 Consent Signals，例如：

- 用户明确希望被提醒；
- 用户主动要求问责；
- 用户表达希望之后继续跟进；
- 用户多次围绕同一目标主动进行复盘。

不得仅因为以下 Vulnerability Signals 推动开启：

- 抑郁状态；
- 孤独；
- 高痛苦；
- 深夜使用；
- 大量 AI 使用；
- 自伤相关内容；
- 明显心理脆弱状态。

系统不得利用脆弱性提高 engagement。

如果用户拒绝开启：

至少 30 天不得再次主动邀请。

如果用户明确表示不希望再次询问：

保持关闭，直到用户主动改变设置。

## 4. Long-term Coaching Patterns

长期模式区分：

- Explicit User Facts
- Working Hypotheses
- Confirmed Coaching Patterns

模型产生的 Pattern 默认是 Working Hypothesis。

未经用户确认：

不得变成永久 Long-term Coaching Pattern。

确认界面未来应支持：

- Confirm
- Edit
- Reject
- Delete

原则：

> Inference must remain a hypothesis until the user recognizes it.

尤其禁止模型自动将以下内容作为确认事实长期保存：

- 精神疾病诊断；
- 人格标签；
- 危险性标签；
- 智力或能力标签；
- 其他高敏感心理推断。

未来应建设用户可见的：

**My Patterns / 我的规律**

页面。

## 5. Human Benefit Measurement

原则：

> Measure outcomes, not intimate content.

Product Analytics 默认不需要访问完整 Coaching 内容。

优先测量：

- Clarity Before / After
- Action Readiness
- Next Step Defined
- Follow-through
- User-rated Helpfulness

数据应尽可能：

- minimal
- aggregated
- pseudonymous
- short-retention
- content-independent

Coaching Data 与 Product Analytics 在架构上应保持逻辑隔离。

普通产品使用数据不得自动用于心理学或医疗研究。

任何 research-grade 数据收集需要独立、明确的 Research Consent。

## 6. Architectural Consequences

V0.3 架构设计必须支持：

- Safety Engine 与普通 Coaching Engine 分离；
- Proactive Care 权限状态；
- Memory Confirmation 状态；
- Working Hypothesis 与 Confirmed Pattern 分离；
- Coaching Data 与 Analytics Data 分离；
- 未来 Trusted Contact 的权限边界；
- Provider-neutral AI Adapter。

## 7. Design Review Rule

每个重要功能在设计与 PR review 时必须回答：

- Does it preserve user agency?
- Does it expose more private data than necessary?
- Does it turn inference into fact?
- Does it exploit vulnerability for engagement?
- Can the user understand and reverse what the system remembered?
- Would this behavior still be acceptable for someone in a severe emotional low?

If any answer is unclear:

**STOP and request review.**

## 8. Step 7 Implementation Boundaries

- Safety Router 可以 veto 任何 Intervention、Challenge 或 Resource Prescription。
- Intervention 必须使用 Evidence Tier；启发性/哲学框架不得包装为科学结论。
- Research Consent 与正常 Coaching Consent 分离。
- R&D Corpus 不是生产 Coaching 数据库的复制品。
- Research Corpus 必须经过 consent gate 和 de-identification pipeline。
- 去标识自由文本仍视为敏感数据，不得声称绝对匿名。
- Resource Prescription Engine 不负责危机资源；危机资源属于 Safety Engine。
