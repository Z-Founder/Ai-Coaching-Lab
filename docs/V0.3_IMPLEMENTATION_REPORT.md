# V0.3 Coaching Engine — Step 7 implementation report

## Scope and dependencies

Single-repository modular monolith using the existing React, TypeScript and Vite.
No dependencies were added or installed. Node 24 native TypeScript execution and
node:test run Golden Tests, with a separate TypeScript test check. Package/lock
version metadata is 0.3.0; dependency ranges and resolved dependency graph are unchanged.
No API credentials are required or collected. No production cloud or release is deployed.

## Data and privacy behavior

- Raw chat, Track fields, action history and outcome feedback live in the current page only.
- A User Utterance stays raw input, not a verified fact. AI Inferences and Working Hypotheses
  remain unconfirmed. Explicit User Facts require a user-confirmed, self-reported claim;
  they are not external verification. Confirmed Coaching Patterns are a separate strategy-only
  memory type. Neither summaries nor model inferences are promoted automatically.
- Memory OFF: no proposal writes. Working hypotheses are session-only in the current UI.
- Confirmed strategies: explicit IndexedDB write with user-confirmation provenance, no cloud
  sync, inspect/edit/delete in My Patterns. Cache and context reads reject unconfirmed
  pattern records, including records labelled "confirmed" without user confirmation.
- Hypothesis expiry uses 14 days OR 3 distinct relevant sessions, first reached. Cross-session
  hypothesis storage is not enabled; helpers define the contract for a future adapter.
- Analytics event records contain only a fixed event name and numeric value, max 200 in memory.
  Optional outcome ratings now write felt-understood, clarity-before/after, agency-before/after
  and helpfulness events only with analytics opt-in; action creation/acceptance write
  next-step-defined/accepted. The event boundary strips extra runtime fields. Analytics failure
  cannot block a Coaching turn. This is not an efficacy study.
- R&D development derivation removes all free text rather than claiming reliable PII scrubbing.
  It creates independent research IDs and rechecks consent before write. Result remains sensitive.
- CloudCoachingStore is the future canonical source; local IndexedDB is cache/offline support.
  No identity record shares a model with coaching text. Production retention/deletion is unresolved.

## Evaluation

Golden Tests cover the 14 requested scenarios, plus safety evaluator failure, contextual signals,
safety latch, provider timeout/abort, malformed/overlong response, expiry, edit/delete failure,
analytics/resource failure, research revocation, stage jumps, proactive cooldown, rest,
outcome missing-data handling, reported-statement separation and corrupt-cache rejection.
Closeout tests additionally cover utterance/inference/fact/pattern provenance, cache/context
promotion guards, content-independent outcome payloads and analytics write failure.

Browser verification uses synthetic text only. Required flows exercised:

- Ordinary coaching: input preserved, one clarifying question, local Mock label.
- Low cognitive load: brief acknowledgement, one question, no growth resource/challenge.
- Track/Learn/Adapt: plan/reality fields preserved across stage selection, different review questions.
- Memory: proposal unconfirmed, explicit confirm, refresh recovery, edit, delete, reject and save-failure status.
- Research OFF: visibly closed while ordinary coaching remains usable; no research capture UI.
- Resource: explicit opt-in, whyNow/reflection/behaviorBridge, local original card and one-per-session limit.
- Safety fallback: evaluator failure suspends ordinary loop; legacy switch, actions, resources and memory hidden/disabled.
- Provider failure: displayed fallback notice, original draft retained, ordinary reflection available.
- Outcome feedback: opt-in ratings appear as name/value-only events; research stays OFF.
- Refresh: raw chat and analytics clear, while confirmed IndexedDB strategies remain available
  only after re-enabling memory consent.

Final command results and final browser checks are recorded in STEP7_PROGRESS.md.

## Risks and review limits

1. The local safety evaluator is not a clinically validated semantic detector. It combines
   limited phrase interpretation, recent context, explicit intent/immediacy/capability and
   persistence signals; it can miss or over-classify real situations. Public deployment is not approved.
2. The response validator checks structural and basic policy constraints, not arbitrary natural
   language safety. A future real provider requires dedicated adversarial and clinical evaluation.
3. Mock replies and pattern proposals are deliberately limited; no diagnosis, hidden profile or
   reliable personalized reasoning is claimed. User-confirmed text remains a strategy note, not fact verification.
4. IndexedDB can be cleared or blocked by the browser; it is not durable backup or encrypted cloud storage.
5. Memory sensitivity filtering is a conservative development guard, not comprehensive detection.
6. Benefit measurements are voluntary self-report. No outcome efficacy or research-grade validity is inferred.
7. Browser E2E is manual tool-driven acceptance, not a committed Playwright automation suite.

## Governance consistency and V0.4+ scope

Human agency is retained through choices, optional actions and explicit challenge consent.
Safety overrides interventions/resources, but never authorizes automatic third-party contact.
Privacy defaults minimize storage; consent flags are independent and research remains OFF.
No engagement streaks, advertising, secret provider key, research mirror or automated diagnosis exists.
Constitution text remains unchanged.

Deferred: production cloud/identity/auth/sync and deletion propagation; real provider server adapter;
clinically reviewed safety evaluator and localized crisis protocol; proactive delivery; Trusted Contact;
cross-session semantic pattern discovery; production research pipeline and granular evidence review;
large libraries, RAG/crawlers, vector databases and complex infrastructure.

Founder decisions needed before moving from local development to a real service: supported ages
and regions; clinical review/ownership of escalation and de-escalation; provider retention/training/
residency requirements; durable retention and deletion policy; research protocol and consent lifecycle.
None requires enabling those services in this Step 7 local implementation.
